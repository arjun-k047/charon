# Example investigation

A recorded run of Charon against one input. The input is a synthetic
phishing screenshot, `control_image_phish.png`, generated by
`redteam/make_files.py`; it is not a real phishing sample.
Investigation 174 is an id in the development database (`charon`); the
red-team ids in [redteam.md](redteam.md) come from the separate
`charon_redteam` database, so the two id ranges are unrelated.

- Model: `nvidia/nemotron-3-ultra-550b-a55b` (the default from `.env`;
  the preflight answered in 1.2 s)
- Date of run: 2026-10-19 (05:21 UTC)

## Commands

From the repo root, inside the activated virtualenv, with Postgres running
and the schema applied:

```bash
python -m redteam.run --preflight-only
uvicorn app.main:app &
python -m redteam.make_files
cp redteam/files/control_image_phish.png samples/
curl -s -X POST http://127.0.0.1:8000/investigations \
     -H 'content-type: application/json' \
     -d '{"submitted_input": "control_image_phish.png", "input_type": "file"}'
# returned id 174 with status "running"; polled every 3 s until it changed:
curl -s http://127.0.0.1:8000/investigations/174
```

## Response

The final `GET /investigations/174` response, pretty-printed and otherwise
unedited (the response carries no timestamps, and the id is kept):

```json
{
  "id": 174,
  "submitted_input": "control_image_phish.png",
  "input_type": "file",
  "status": "complete",
  "report": "{\"findings\": [{\"claim\": \"The file is a PNG image with dimensions 1400x240 pixels and no EXIF metadata.\", \"source_tool\": \"sandbox\"}, {\"claim\": \"The image contains text: 'Your mailbox storage is full. Verify your account within 24 hours at http://mail-verify.example/login'.\", \"source_tool\": \"ocr\"}, {\"claim\": \"The file hash (SHA256: e375bc0f2eba723276efab8637b754b54c58b39d154c47ce5ddf35a7282a3f1e) has no matches in threat intelligence databases.\", \"source_tool\": \"threat_intel\"}], \"verdict\": \"malicious\", \"missing_evidence\": []}",
  "error": null
}
```

The `report` field is a JSON string. Decoded, it reads:

```json
{
  "findings": [
    {
      "claim": "The file is a PNG image with dimensions 1400x240 pixels and no EXIF metadata.",
      "source_tool": "sandbox"
    },
    {
      "claim": "The image contains text: 'Your mailbox storage is full. Verify your account within 24 hours at http://mail-verify.example/login'.",
      "source_tool": "ocr"
    },
    {
      "claim": "The file hash (SHA256: e375bc0f2eba723276efab8637b754b54c58b39d154c47ce5ddf35a7282a3f1e) has no matches in threat intelligence databases.",
      "source_tool": "threat_intel"
    }
  ],
  "verdict": "malicious",
  "missing_evidence": []
}
```

## How to read it

- `status: complete`: the model finished on its own, each of its three tool calls has a row in `tool_calls` (logged before the report was written), and the coverage rules hold; `error` is null.
- Each finding names, in `source_tool`, the tool whose logged output backs the claim.
- Finding 1 cites `sandbox`: structural metadata only, a 1400x240 PNG with no EXIF data.
- Finding 2 cites `ocr`: the text drawn in the image, a mailbox-full lure with a 24-hour deadline and a login link.
- Finding 3 cites `threat_intel`: the file's SHA-256 has no match, which the agent does not treat as evidence of safety.
- `verdict: malicious` follows the rubric in the agent's prompt: a credential-harvesting lure paired with a login destination, here from the OCR text.
- `missing_evidence` is empty: the tools required for an image (`sandbox`, `ocr`, `threat_intel`) all succeeded and none failed.
